# City — 城市基础生成实验

> 更新：2026-10-06。功能实施已接入现有三层契约；本文件的验证结果只记录实际执行输出，不以代码检查代替运行验收。
> 专用实现目录：`Assets/Mine/Scripts/TerrainManager/TerrainType/City/`。

## 目标与边界

生成近乎平面的 3D 俯视城市地图：先建立贯穿地图的十字正交车行道／人行道，路网间隙形成矩形街区，再分配园区大类与子类型、沿街放置完整设施，最后分布绿化地被。独立入口为 `Assets/Scenes/CityScene.unity`，方案资产为同目录的 `CityExperiment.asset`；不覆盖或合并 `AlgorithmScene`，不修改郊野资产与生成流程。

初版仅验证规则、占地及数据消费：设施和树为完整 Cube 占位体，公园草坪和未开发区野草使用现有批次表现。真实建筑预制体、道路曲线／层级交通、施工动画、WFC、社会模拟、最终植被着色、跨场景拼接均不在本轮范围。

## 生成流程与责任

1. `TerrainGridRoadGenerator` 是 `TerrainGenerator/` 下的通用算子，只生成正交道路带与矩形街区，不含城市用途或设施类型。车道交叉处优先于人行道，边界道路完整保留在地图内部。
2. `CityLayoutGenerator` 按园区权重分配街区数量，使用最大余数与最低启用子类型数量保底；按四邻接进行轻聚类，工业区带轻量靠边偏好；在各园区内按子类型权重分配。道路和设施候选不会被 Voronoi 或最终噪声弯曲。
3. `CityMapGenerator` 写入通用 `TerrainMapData`：道路格覆盖为 `1`、基础地区为 UrbanBase、无地点／地区组归属；街区格覆盖为 `0`、保存子类型及相应地点／地区组。地表高度为 `0`。城市的地点／地区组代表街区，不是多个街区合并后的行政区。
4. `CityStuffDistributor` 优先处理占地较大的设施，按实际矩形在沿街槽位放置，四方向朝向；保留入口和设施间距。树在主设施之后填空；有限尝试不足时跳过并由 `CityStuffResult` 报告，不自动缩小原始设施。完整矩形检验地块与道路；通用植被避让 Radius 保守包住设施及其入口，不作为设施间的圆碰撞限制。
5. `CityTerrainType` 集中方案参数、ID 外观及分布编排：公园／未开发区规则存在且密度大于零时，委派通用 `TerrainPlantDistributor` 分布草坪／野草。可删去未使用的绿化子类型，不要求每个城市方案启用全部 8 类。
6. 现有 `TerrainManager`、`TerrainMeshGenerator`、`TerrainSceneRenderer` 与 `TerrainPlantRenderer` 直接消费通用数据和计划；无需城市专用 Manager 或共享渲染层的类型分支。

同配置、同随机种子生成相同输出。方案资产不缓存某次布局，设施及地被从地图尺寸、原点、种子和本方案参数确定性重建；地图生成后修改方案参数需要整图重生成，不在一张旧地图上混用新配方。

## 默认参数

| 参数 | 默认 | 说明 |
|---|---:|---|
| 地图／格距／Chunk | 300×300／1／50 格 | 通用 Manager 参数，默认 36 个地表块 |
| 街区列／行 | 6／6 | 路网先行形成默认 36 街区；不足最小尺寸时自动减数 |
| 主干道间隔 | 3 | 内部每三条及两侧边界为主干道；设为 0 禁用主干道 |
| 主干车道宽／支路宽 | 8／4 | 世界单位，主干宽不得小于支路宽 |
| 人行道宽 | 2 | 每侧宽度；设为 0 禁用，不允许小于一个逻辑格的非零宽度 |
| 最小街区跨度 | 24 | 道路以外的可用跨度；极小地图明确拒绝生成 |
| 建筑退界 | 2 | 世界单位，沿街保留入口；间距当前固定 1.5，入口宽最多 2.5 |
| 园区权重 | 工业20／居民40／科技25／绿化15 | 按街区数量配额；当前同一地图街区等面积，非任意形状的精确面积配额 |
| 各子类型权重 | 1 | 均分所属园区数量；数量足够时确保每个启用子类型出现 |
| 公园／未开发地被密度 | 0.3／0.5 | 委派通用 Plant 规则，实际输出仍受道路、边界和设施入口避让限制 |

设施上限依次为工厂2、工地1、别墅4、平民窟10、办公4、研发2、公园1、未开发0（每街区）；树目标依次为0、0、1、0、1、1、6、10。无足够占地时不是必须填满的硬约束。配置车道或非零人行道窄于逻辑格时明确拒绝，避免栅格漏采使路网断裂。

## 文件与操作入口

运行文件为 `CityContent.cs`、`CitySettings.cs`、`CityLayout.cs`、`CityLayoutGenerator.cs`、`CityMapGenerator.cs`、`CityTerrainType.cs`、`CityStuffDistributor.cs`；方案 Inspector、独立场景创建与回归位于 `Editor/`。

`Tools/Terrain/City/Create CityScene`／`CityExperimentSetup.Create()` 以 Additive 创建独立空场景，只保存新方案资产与新场景，不保存或关闭原场景。若场景、资产或其 `.meta` 已存在则拒绝覆盖。新场景为相机、方向光、City Experiment 三个根，Manager 引用城市资产并在 Play Mode 生成。

进入 Play Mode 前只保留本次要测试的场景，防止 Additive 中两个 Manager、相机同时运行；关闭原场景前检查其未保存状态，不保存或丢弃用户调整。创建工具不修改 Build Settings。城市参数位于类型资产 Inspector；调整后使用 Manager 的 `Regenerate Terrain`。

默认回归检查 8 子类型、格归属／地点／地区组、完整确定性、路网四邻接连通与交叉车道、设施实际矩形不跨街区／道路或重叠、入口不被设施／树／地被阻挡、完整植物圆占地与保守设施避让，以及共享颜色图／Mesh／Renderer 消费和幂等释放。以上统计来自本轮实际执行，Play Mode 日志无新增错误；项目其它模块的既有过时 API 编译警告未在本轮处理。布局密度、占位颜色及美术观感仍待人工观察，不以功能断言代替视觉验收。

场景创建过程中发现新 Additive 场景已激活时再次调用 `SetActiveScene` 返回 false；创建工具已改为仅在未激活时调用，已保存的城市方案资产保持不变。中断产生的空场景直接补全并保存到新路径，没有删除或覆盖现有场景／资产。创建前的主计划和郊野场景副本位于项目根 `.backup/city-foundation-20261006/`（不是完整代码快照）；`AlgorithmScene` SHA-256 与该副本一致。
