## 当前方案（2026-09-28）

面向 3D 俯视角的近乎平面地图，默认 300 × 300 世界单位。`TerrainManager` 只编排生成和表现提交；`TerrainMapData` 是区域、所属种子、连通区域组、道路覆盖与高度的唯一数据源。现行顺序为：初始化草地底层 → 按六类非草地规则放置相斥种子 → 最近种子归属及 Voronoi 距离差阈值生成特征区 → Voronoi 胞边道路覆盖所有区域 → 对地区与道路统一做最终数据扰动 → 派生连通组与水域下凹 → 生成地表、稀疏完整个体和密集地被。相同配置与种子应得到相同结果；不再生成地点连接路线，也不要求道路连通或避开水域。

| 层 | 现行组件 | 产物与约束 |
|---|---|---|
| 数据 | `TerrainDataGenerator`、`TerrainVoronoiSdf`、`TerrainRoutePlanner`、`TerrainDataNoise` | `TerrainMapData`；后者虽沿用 Planner 名称，实际只写胞边覆盖，不做 A*/MST 寻路。 |
| 地表 | `TerrainMeshGenerator`、`TerrainSurface.shader` | 连续分块 Mesh 与颜色图；地区色先柔化，道路再以固定土黄色 `(0.70, 0.55, 0.28)` 按覆盖度叠加。 |
| 稀疏内容 | `TerrainStuffDistributor` | 房屋、风车、森林树及果树的确定性占位计划；当前用简单几何表现。 |
| 密集地被 | `TerrainPlantDistributor`、`TerrainPlantRenderer` | 矮草、高草、小麦、花的密度规则与分批实例面片；树不属于 Plant。 |
| 编排 | `TerrainManager` | 全部生成成功后替换旧结果；重复生成和退出时释放 Mesh、纹理、材质及植被渲染资源。 |

### 当前面板与数据语义

Inspector 按生成顺序分为 Scene、Map、Feature Seeds、Voronoi Regions、Voronoi Roads、Final Data Warp、Sparse Content、Dense Vegetation。四个 Voronoi 参数保持滑杆：`Region Width` 控制特征胞内覆盖范围，`Region Softness` 只柔化地区距离场；`Route Width` 对种子距离差取阈值，`Corner Softness` 柔化路口。Play Mode 调整这四项会立即重生成，其余参数调整后使用 `Regenerate Terrain`。`Feature Seeds` 的半径影响种子相斥与扰动的核心保护，不是现行地区圆形边界。草地没有种子规则；道路在所有地区上层，统一为 Dirt，跨水域只有颜色覆盖，不生成桥面。`Depression Depth` 仅使水域地面下凹，不提供独立水面。

### 验证与后续

入口为 `Assets/Scenes/AlgorithmScene.unity`。`Tools/Terrain/Validate Experiment Data` 和 `Tools/Terrain/Validate Voronoi Distribution` 验证确定性、区域/道路阈值、宽度与柔化、占地及消费层；Play Mode 检查生成数量、日志与重复生成后的资源清理。视觉自然度、道路跨水表现、真实预制体及植被 Shader/LOD 尚待后续迭代。`TerrainRoadType.Stone` 仅留作旧数据契约兼容，生成器不再输出；旧树类 Plant 规则的反序列化迁移仍保留，待确认兼容窗口后再删除。此两项不是现行模式开关。

## 历史实验记录（以下内容不代表当前实现）

## 目标与边界

为 Unity 6 + URP 17+ 的 3D 俯视角游戏生成一张可配置的近乎平面地图。首个实验地图默认大小为 300 × 300 世界单位，以草地为基底，包含村落、麦地、森林、水域四个平级区域特征及连接陆地点的道路。初期用不同颜色的简单几何体表示房屋、风车、树、草和小麦，验证从数据生成到地表着色与内容分布的完整链路。

首轮只要求功能正确和可重复生成。暂不实现 `PlantGenerator`/`PlantManager`、真实建筑预制体、天气、动物、复杂水体、山体、全图 WFC、运行时流式加载或最终美术材质。当前扩展试验加入单块蓝色下凹水域：地表基准高度为零，水域内部最低为 -1 世界单位；这只是水域数据和地形凹陷，并无独立水面或流体。

## 术语与默认假设

- **地图大小**：300 × 300 指世界空间的 XZ 尺寸，不等于逻辑单元数量。
- **逻辑网格**：保存区域、道路、可选高度等权威数据。初版建议 1 世界单位/格，即 300 × 300 个单元；格距是配置项。
- **地表网格**：用于绘制的分块 Mesh，从逻辑数据采样；建议先以 50 × 50 世界单位为一个渲染块，避免单块顶点过多。分块尺寸是实现起点，不是固定规则。
- **区域**：`Grassland` 为默认区域；`Village`、`WheatField`、`Forest`、`Water` 为覆盖它的区域特征。水域不生成道路或地面占位物。
- **道路**：由连续路线、宽度、覆盖遮罩和路面类型共同表示。路面类型可随所在区域变化，例如草地段为黄土路、村落段为石路。
- **占地**：内容分布时用于避让道路和其他内容的空间范围；属于分布结果，不回写基础地图数据。

## 组件与职责

| 组件 | 输入 | 输出及职责 |
|---|---|---|
| `TerrainManager` | 配置、种子、场景引用 | 顺序调用三个生成器、提交可视化结果、清理旧结果；不持有区域和放置算法 |
| `TerrainDataGenerator` | 地图配置、种子 | 生成 `TerrainMapData`：区域、地点、道路、可选高度；基础数据的唯一权威来源 |
| `TerrainRoutePlanner` | 区域数据、陆地点、道路宽度 | 为数据生成器选择最小连通路网，以带区域代价的 A* 绕开水域并简化路线 |
| `TerrainMeshGenerator` | `TerrainMapData`、地表配置 | 生成分块地表 Mesh 与着色输入；不得改变地图数据 |
| `TerrainStuffDistributor` | `TerrainMapData`、分布配置 | 生成 `TerrainStuffPlan`：类别、位置、朝向、尺寸、占地；不实例化场景物体 |
| 实验表现适配 | 地表结果与 `TerrainStuffPlan` | 将地表提交给 MeshFilter/Renderer，并用简单几何体显示放置点；后期替换为预制体与植物系统 |

依赖方向固定为：`TerrainDataGenerator → TerrainMapData → TerrainMeshGenerator / TerrainStuffDistributor → TerrainManager 提交表现`。Mesh 与分布器彼此不依赖。生成方法可以先同步执行；若以后改为异步或分块任务，上层契约仍以本次生成结果为准。

## 最小数据契约

`TerrainMapData` 包含版本、种子、世界原点、世界尺寸、格距和单元尺寸；每个逻辑单元至少有区域类型与可选高度。道路单独保留连续路线/连接关系，并提供可采样的覆盖率与路面类型。地点至少有类型、中心、范围和稳定 ID。区域与道路是正交数据层：一块麦地可被道路穿过，道路不会把该处的麦地区域改写掉。当前四个特征地点先生成并参与区域归属，之后才进行避水寻路与道路栅格化。

`TerrainSurfaceResult` 包含地表分块的网格、世界范围和着色输入。初版建议用从 `TerrainMapData` 烘焙出的地表颜色/控制纹理驱动 Shader；具体通道编码在实现着色器时确定。每个分块使用统一世界坐标采样，保证相邻块颜色与边缘顶点连续。双网格在此表示“逻辑数据网格 + 表现网格”，后者不是第二份地形权威数据。

`TerrainStuffPlan` 是有序的放置记录集合。记录至少包含稳定 ID、内容类别、变换、占地边界和来源区域。占地检查在分布器内部进行，优先保留道路和关键建筑位置，再布置密度较高的树、草和小麦。表现适配器只负责把这些记录显示为几何体，不决定分布。

首轮使用独立的随机子种子生成区域、路线和内容，避免仅修改草的密度就改变村落布局。相同输入在同一实现版本内应产生相同结果。

## 初版生成顺序

1. 验证配置；建立共享坐标系与确定性种子。
2. `TerrainDataGenerator` 对村落、麦地、森林和水域做排斥选址，以有限加权沃洛诺伊分区填充草地基底上的特征；水域区域产生下凹高度。
3. `TerrainRoutePlanner` 连接陆地点的最小生成树，A* 绕水寻路；再按区域映射路面类型、栅格化道路覆盖数据。
4. `TerrainMeshGenerator` 采样数据生成分块平面 Mesh；高度只影响顶点 Y 值。区域底色先平滑，再叠加随底色提亮的道路颜色图。
5. `TerrainStuffDistributor` 在道路和建筑占地约束下输出放置计划。村落放房屋，麦地放风车与小麦，森林放树，剩余草地区域放草；数量、间距与占地参数由配置控制。
6. `TerrainManager` 在全部结果有效后替换场景中的旧生成结果；实验表现层绘制 Mesh、设置地表材质并显示分类占位几何。

路线生成和占地分配先采用可读、可测试的规则/搜索算法。WFC 保留为未来可替换的复杂布局求解器，首轮不将其作为完成条件。

## 路径与区域优化选型依据（首轮方案记录）

初版三个地点围绕固定归一化坐标做轻微扰动，区域用半径和 Perlin 噪声修边；道路固定生成三条弯曲连线。这个骨架适合验证数据链路，但增加地点或水域后容易出现地点间距不均、冗余路线和障碍穿越。下述方向已用于本轮第一版优化，尚未实现通用 Poisson disk、可配置环路或区域面积配额。

1. **地点采样**：用最小间距采样（Poisson disk）生成候选地点，再按区域面积、相邻关系和地图边界筛选；比纯随机点更容易保证村落、麦地和森林不互相挤压。参考 Bridson, *Fast Poisson Disk Sampling in Arbitrary Dimensions*：https://www.cs.ubc.ca/~rbridson/docs/bridson-siggraph07-poissondisk.pdf 。
2. **区域塑形**：从地点建立距离场或 Voronoi 风格的归属场，叠加低频噪声形成不规则边界，最后用连通性与面积约束修正孤岛。噪声作为边界扰动而非独立地貌权威。参考 Red Blob Games, *Making maps with noise functions*：https://www.redblobgames.com/maps/terrain-from-noise/ 。
3. **路径网络**：地点先构图，选取最小连通骨架并按需求加入少量环路；每条边再用带代价的 A* 求路线，水域禁行或高代价、坡度和区域边缘作为软代价，最后栅格化宽度与路面类型。参考 Red Blob Games, *Introduction to the A* Algorithm*：https://www.redblobgames.com/pathfinding/a-star/introduction.html 。

后续可把当前固定类别的有限候选排斥采样升级为通用 Poisson disk，再加入区域面积配额和可配置环路；路网总长、区域覆盖与跨水域违规数仍作为衡量指标。

## 首轮水域下凹试验（历史记录，选址已升级）

`DepressionDepth` 默认值和 `AlgorithmScene` 的场景值均为 1。早期版本在道路生成后寻找空白草地放水；这一选址流程已由下节的平级地点分布取代。现版本中深度为 0 只会让水域变平，不会删除水域区域。地表网格读取高度；分布器因区域不匹配而不在水域放占位物。若需要真实水面，应新增独立水面表现，而非把蓝色凹地当作液体。

2026-09-26 验证：默认种子得到 1,516 个水域单元，最低逻辑高度和地表 Mesh 顶点高度均为 -1；水域无道路覆盖，颜色图中的水域像素呈蓝色，内容占位仍为 401 个。种子 42–46 均生成水域。Unity 重新编译成功，EditMode 数据验证通过；Play Mode 保持 36 个地表块与 401 个占位物，退出后无生成物残留。画面观感仍需在 Editor 中人工确认。

## 区域与道路迭代计划（2026-09-26）

本轮采用“带尺寸的有限沃洛诺伊”而非无限硬分区：村落、麦地、森林、水域四个地点通过确定性候选采样保持边界留白和彼此间距；每个格点由归一化距离最低且仍处于影响半径内的地点占据，其余继续为草地。局部噪声只扰动边界，不改变地点中心。水域直接进入同一地点和区域判定流程，高度只在水域权重内下凹。

- [x] 数据层：四类地点平级，排斥采样与有限加权沃洛诺伊分区；验证中心、间距、种子和连通性。

## 数据层顺序与 SDF 对照重构（2026-09-27）

当前生成顺序为：①显式初始化草地底层；②放置非草地特征种子；③按所选 SDF 生成地区；④按所选模式生成边界道路；⑤用同一坐标噪声重采样地区、归属和道路；⑥从最终地区派生连通分组与水域下凹。后两项是最终数据的派生缓存，不参与前面的形状判定。地表、Stuff 与 Plant 仍只消费最终 `TerrainMapData`。

Inspector 的两组按钮各自独立：地区可选 Circle SDF，或将种子半径与沃洛诺伊胞边内缩 SDF 相交的 Voronoi Polygon SDF；道路可选原有等宽边界刷，或用沃洛诺伊胞边的解析 SDF 阈值着色。胞边内缩为道路留出草地走廊，小地图时内缩量受种子半径限制。Play Mode 点击模式按钮会立即重生成，也可点击 Regenerate Terrain。噪声位移设为 0 可以观察原始 SDF；非零时地区与道路一起变形。

`TerrainVoronoiSdf` 提供两种模式共用的胞边距离，地区生成器不依赖道路生成器；`TerrainDataNoise` 只处理已有栅格层，种子坐标保持稳定，避免改变后续内容的地点锚点。

## SDF 分布语义修订（2026-09-27）

上节记录初版对照方案；现行实现将四种判定来源明确分开。标准地区用地点半径的圆形 SDF；Voronoi 地区仅用所属胞的胞边 SDF，阈值为“种子中心到最近胞边的距离 − Voronoi Region Width”，宽度越大，地区越大。阈值下限保留草地走廊，避免地区覆盖胞边道路；不再以圆形半径裁切 Voronoi 地区。种子位置在两种模式间保持一致，现有半径仍参与种子选址的相斥计算，但不参与 Voronoi 地区着色。

标准道路按可通路种子的最近邻连线生成等宽线段／胶囊 SDF，不强制路网连通；Voronoi 道路按解析胞边 SDF 和路宽阈值生成。两者都只写入草地，以避免覆盖水域和其它地区。最终噪声仍统一扰动地区、归属和道路。Inspector 在 Voronoi 地区模式显示独立的区域宽滑杆，实验验证检查区域与道路宽度的单调性以及两种道路分布确有差别。

## 地区与道路分层、变宽道路（2026-09-27）

本节替代上节的道路和草地走廊规则。草地是基础层，非草地特征按圆形或胞边 SDF 覆盖其上；地区判定不再为道路预留草地走廊。道路覆盖层与地区层独立：标准模式对所有种子做最近邻连线，Voronoi 模式对所有胞边着色，不再受 `ConnectRoad` 或地区类型约束。最终数据噪声同时重采样地区与道路，也不会在非草地地区清除道路。着色层先得到地区色，再按道路覆盖度叠加道路色；道路上的建筑和植物仍按占地规则避让。

Voronoi 道路的阈值输入从“到胞边的几何距离”改为最近与次近种子距离差 `½(F₂−F₁)`。它在胞边为零，但沿边和种子间距变化时并非恒定的几何距离，因此同一路宽阈值产生宽窄变化。`Road Width` 在标准模式是几何宽度，在 Voronoi 模式是距离差阈值；两者数值不能视为严格等价。水域仍由地区层决定下凹，跨水道路目前仅在下凹地表上叠加颜色，不生成桥面或抬升几何。

## 独立道路宽度控制（2026-09-27）

上述两种道路宽度现已拆成独立参数：`Road Width` 只控制标准种子连线的几何宽度，`Voronoi Route Width` 只控制 Voronoi 距离差阈值。Inspector 随道路模式显示对应滑杆，Play Mode 改动后立即重生成。新参数默认值为 5，与迁移前场景中的道路宽度一致；验证确保两个滑杆各自改变对应模式而不影响另一模式。

## Voronoi 道路收腰与土黄色调色（2026-09-27）

道路配色由“根据地区色提亮”改为土黄色：土路为较深的黄褐色，石路为较浅的沙黄色；地表颜色图仍按道路覆盖度叠在地区色之上。Voronoi 模式新增 `Voronoi Waist Strength` 滑杆（0–4，默认 2）：原距离差 `½(F₂−F₁)` 再乘以 `clamp(L/(F₁+F₂), 0.55, 1)^Strength`，其中 `L` 是最近两种子的间距。两种子连线附近的比值约为 1，维持中段基准宽度；远离连线、靠近胞边交汇处时比值下降，路面向外扩宽，因而俯视轮廓的中段收窄更明显。强度 0 恢复上一版算法。实际可见程度仍受 `CellSize` 采样精度限制，低于约 1–2 个格宽的变化会被栅格化削弱。

## Voronoi 道路距离场平滑实验（2026-09-27）

本节替代上节的收腰公式，不再按种子间距乘幂拉宽道路。新 `Voronoi Corner Softness`（0–8，新地图默认 3）直接在 Voronoi 道路距离场生成时，用次近与第三近种子的距离差做稳定的两项 smooth-min：`g₂ − k·log(1 + exp((g₂−g₃)/k))`，其中 `g₂=(F₂−F₁)/2`、`g₃=(F₃−F₁)/2`、`k` 为柔化范围。普通边段两项差距大，基本保留原始宽度；三胞交汇附近两项接近，距离场自然降低，道路轮廓圆润且节点较宽。`k=0` 恢复原始距离差；旧 `_voronoiWaistStrength` 序列化值迁移到新字段，方便现有场景继续调参。该实验只改变道路覆盖层，不弯曲 Voronoi 的直线胞边或更改地区归属。

草地现在是基础层，不生成草地种子；旧场景已序列化的草地规则暂被忽略，并由 Inspector 提示。旧 `RoadBend`／`LoopRatio`、A*/MST、`TerrainRoute` 契约与折线栅格化已从代码清理；旧场景 YAML 中尚未保存迁移的字段不影响运行，重新保存场景时由 Unity 清理。`AlgorithmScene` 原有地点数量和噪声滑杆值未被本次覆盖。

## Voronoi 单模式与地区柔化（2026-09-28）

本节为当前实现；上文的圆形地区、种子连线道路和双模式对照仅保留为历史记录。数据层固定按最近种子决定胞归属，再以平滑种子距离差场 `½(F₂−F₁)` 对该胞地区取阈值；地区中心处的同一距离差减去 `Voronoi Region Width` 作为边界阈值。`Voronoi Region Softness`（0–8，默认 3）独立于道路的 `Voronoi Corner Softness`，只影响地区遮罩，不改变最近种子归属。两者为 0 时各自恢复未经 smooth-min 柔化的距离差。种子配方半径仍用于种子间距，不参与地区着色。

道路固定在所有地区之上按 Voronoi 距离差阈值生成；`Voronoi Route Width` 与道路柔化仍分别控制覆盖宽度与交汇处轮廓。Inspector 不再提供地区或道路模式按钮，四个 Voronoi 滑杆可独立调节，Play Mode 调节后会重生成。旧模式枚举、序列化模式字段、旧标准道路宽度、圆形地区与种子连线道路实现均已删除，现有场景中尚存的旧序列化字段由 Unity 忽略；未修改 `AlgorithmScene` 文件。EditMode 验证改为 Voronoi 单模式，包含地区/道路宽度单调性、各自柔化、种子硬归属、噪声影响与消费层契约。
