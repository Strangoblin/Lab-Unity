# 记忆归档判据

> 记忆是结论的**当时快照**；活文档是结论的**当前位置**。记录过期不是因为它旧，是因为它的结论
> 已经在别处生效了 —— 旧只是它被发现的时机。别把年龄当理由。

## 两条通道，不要混

| 通道 | 触发 | 处理 |
|---|---|---|
| **孤儿** | 索引里没有它（`index_mentions == 0`） | 立即分流：补进索引，或并进别处再删。孤儿不需要等过期 |
| **过期** | 年龄 ≥ 60 天 | 走下面的三把锁 |

孤儿往往比过期更急：一条没有索引的记录等于不存在，但它照样占着检索面。

## 三把锁（全开才退役）

| 锁 | 判据 | 怎么算 |
|---|---|---|
| **旧** | 记录日期 ≥ 60 天 | `inventory.py` 的 `age_days` |
| **无活引用** | `knowledge` / `skills` / `agents` 里没有文件按文件名引用它 | `live_links == 0` |
| **有归宿或已无价值** | 每条还有用的结论都能在活文档里找到，**或**内容只对已退役系统有意义 | 人读；grep 核对 |

`index_mentions` 是辅助信号，不是锁：

- `0` —— 孤儿通道
- `1` —— 只有索引表那一行，正常
- `>1` —— 索引正文另有引用（如「关键架构决策」段），先看它引的是什么再决定

## 去向优先级

| 内容形态 | 去处 |
|---|---|
| 流程、操作、判据、检查清单 | skill 正文或 `references/` |
| 当前事实、契约、参数、API 行为 | `.agents/knowledge/**` |
| 不变结论 | 域索引的不变式段（「技术栈」「关键架构决策」），一行 + 指向 knowledge |
| 纯历史（当时为什么这么选、踩了什么坑） | `history.md` 一行，正文删掉 |

**一个结论只有一个当前位置。** 如果它已经在 knowledge 里，就不要再搬进 skill；如果它已在索引
不变式段，就不必再进 knowledge。

## 历史日志

`.agents/memory/meta/history.md` 与 `.agents/memory/unity/history.md`，**逐日一行**，不是逐条：

```markdown
| 日期 | 当天做了什么 | 归档记录 | 去向 |
|------|-------------|---------|------|
| 2026-08-06 | POSS 逐物体软阴影落地（Atlas + 屏幕空间 PCF，投影 10m 硬编码）；同日修 SSR DDA 鱼眼 w 翻转 | poss-per-object-soft-shadow, ssr-dda-fisheye-w-sign-flip | knowledge/unity/shader/postprocess/shadow.md |
```

规则：

- 一天多条的合并成一行，`归档记录` 列列出 slug，保留可追溯性
- `当天做了什么` 写**结果**，不写过程；不超过 60 字
- `去向` 写可点的相对路径；内容不留的写清楚留痕在哪（`deletes.jsonl`）

## 索引改写

1. 删掉退役行
2. 在「Memory 文件」表尾追加一行指向历史日志，四列依次写：`history.md` 的链接、
   `—`、`已归档记忆时间线，逐日一句`。

3. 如果退役记录在「关键架构决策」「活跃上下文」段被文字引用过，改写那处引用指向新的活文档

## 证据目录

`memory/<域>/evidence/<记录 slug>/` 是记录的附件。规则：

- 所属记录退役、且没有活文档引用该目录时，**才可以**一并退役
- **单列一批、单独确认**，不跟着记忆自动走 —— 体积大不等于过期，混在一起会被顺手清掉
- 证据目录是入库文件，`cli.py delete` 删除后仍可从 git 取回

## 不要拿这些当理由

| 反例 | 为什么不行 |
|---|---|
| 「这条太旧了」 | 年龄只是时机。结论没搬家就不能删 |
| 「内容我看懂了」 | 你看懂不等于下一个人能看到。要 grep 到 |
| 「反正 git 里有」 | git 里有的是**内容**，不是**可检索的结论**。归档的价值是省掉重新翻历史 |
| 「索引太长，删几条好看点」 | 索引长度是症状不是病。退役后必须让结论有新的位置 |
| 「这条和另一条很像」 | 先确认是不是重复；重复的合并，**不是**直接删一条 |
