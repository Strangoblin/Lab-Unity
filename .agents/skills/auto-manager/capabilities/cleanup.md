# Cleanup — 按用途清理

落点、长期归属与生命周期以 [会话产物规范](../../../knowledge/meta/interfaces/task-artifacts.md) 为准。清理范围由任务授权决定；文件名、扩展名、年龄和未被场景引用只能作为调查线索。

## 阶段收尾

- runner 自己新建的可重建 fixture 用 `finally` / trap 收尾；保留失败现场须报告路径和原因。
- 会话脚本先判断复用价值与复现依赖，再归属正式 scripts、功能 `Validation~/` 或必要证据。
- 不扫描删除 `tmp/*.cs`；不把 `tmp/.reusable/` 当永久库；不为每次验证创建备份包。

## 存量整理

1. 读取既有计划、memory、脚本调用和资产 GUID 引用，确认用途及是否唯一副本。
2. 给出精确文件清单：动作、理由、Git 状态、内容摘要或哈希、调用/引用及归档目标。存在脏改动时保留原有工作。
3. 有用测试连同必要输入一起准备归档，修正路径并复跑；可重建二进制、复制项目与日志单列。
4. 按根 AGENTS.md 取得清单确认后，执行前复核内容未变；已获明确授权的同一清单不反复确认。
5. 项目资源接口 `asset.root` 对应受管范围的写/删/移走 Unity 门禁。资产与 `.meta` 成对处理，移动保留 GUID；空目录直接删，非空目录加 `recursive` 后由同一闸展开子项逐个判定（软链与作用域根拒绝）。
6. 完成后更新活动引用和验证入口，报告实际保留/归档/删除结果，将结论与证据交角色回写 memory。

## 功能与场景

调试日志、临时 GameObject、注释代码、空目录和未引用资源先确认业务用途；不要从名称推导删除或改层级。场景整理须在任务范围内，并遵循 [scene-setup.md](scene-setup.md)。

正式查询/整理脚本见 [脚本索引](../../unity-editor/scripts/roslyn/README.md)。Git 回退和验证基线见 [backup.md](backup.md)。
