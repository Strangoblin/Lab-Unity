# 错误恢复与退出

先保存本次错误、日志/堆栈与实际验证范围。编译通过、结构正确、视觉符合预期是不同结论，按证据报告。

## 按模式恢复

| 模式 | 行为 |
|---|---|
| Research | 编译失败报告定位与诊断建议，等待人工决定；不自动修复 |
| Production | 定位已知错误并自动修复，最多 3 次；同一错误连续 2 次，第 3 次前暂停重审 |
| Experiment | 阶段前 2 次失败可修复；第 3 次联网确认疑点、更新 Plan；最多 3 大循环，失败保留现场 |

未知错误不盲目修复。连续 2 个大循环卡在同阶段，先说明方案疑点再继续。
桥接或命令故障由 [Editor 可用性流程](../../unity-editor/references/availability.md) 处理，不在本 skill 重复维护。

## 人工观测与决策

- 渲染颜色、透明度、动画与视觉参数由人工在 Editor 观测；交互无法自动复现时请人工验证。Profiler/Frame Debugger 或 benchmark 结果按实际工具口径说明。
- Research 每步等待观测；Production 在异常或需人工决策时暂停；Experiment 在 Plan 确认和授权/失败边界暂停。
- 架构选择、主观参数和影响数据的 SerializedReference/.meta 变更按任务授权处理。已有明确决定直接落实，不重问已授权事项。
- 不把编译通过、Play 通过或功能就绪自动变成额外批准节点。当前任务已授权的验证继续执行；提交只在已有授权时执行。

## 退出与报告

目标达成后报告已改内容、实际编译/运行/渲染证据及未验证项。
同一错误达到修复上限、Editor 操作超过 60s 无进展或 bridge 持续断连时停止依赖步骤，保留现场并给最小后续动作。
Editor 不可用时可完成独立代码工作，注明跳过编译/运行的原因；不声称效果通过。
按 [产物规范](../../../knowledge/meta/interfaces/task-artifacts.md) 收尾，把可复用结论交 [角色 memory](../../../memory/unity/MEMORY.md) 记录。
