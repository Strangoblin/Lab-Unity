# 完整性核验

用于 Production `[P2b]`，在知识取用后、修改计划前，对每个目标文件逐项对照适用规范。

1. 读取目标代码、其规范及至少一个已声明且类型匹配的参考实现；资源路径按项目资源接口解析。
2. 输出 `规范条目 | 状态 | 当前代码 | 修改计划` 表。状态为符合、不符合、不适用；不适用附理由。
3. 将授权范围内的不符合项并入 `[P2c]` 计划；需要扩大目录或改动范围时按 [执行契约](execution-contract.md) 处理，不借核验扩写任务。
4. 修改后核对计划是否落实；证据不足明确列未验证项。

只检查实际适用条目，例如文件头格式、复杂计算独立函数、函数内注释与 Pass 命名。
不能用“大致读过”“先改再说”替代明确对照，也不能以规范推断替代已有参考实现。
本核验属于 skill 质量流程；MCP 的实际 block/warn 判定仍由现行策略控制。
