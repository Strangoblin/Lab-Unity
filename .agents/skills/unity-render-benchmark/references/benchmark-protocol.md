# 渲染同步墙钟 A/B 协议

用于 [unity-render-benchmark](../SKILL.md) 的采集器适配与报告判读。用户主要需要相对耗时，默认选同步墙钟；仅在需要纯 GPU/逐 Pass 时间时选对应工具，并按其合同处理，不混算两种口径。

## 采集合同

| 项 | 要求或建议 |
|---|---|
| 被测量 | GPU-synchronized render-request wall milliseconds，明确不是纯 GPU 时间 |
| 核心操作 | Stopwatch 开始 → `SubmitRenderRequest` → 记录提交段 → 对目标 RT `ReadPixels(1×1)` → 停表 |
| 同步含义 | 回读等待目标纹理可读，避免仅测到命令提交；不声称整块 GPU/所有队列完全空闲 |
| 计时边界 | 包含请求的 CPU/驱动/渲染/等待与单像素回读；这些可能重叠，不能据差值分离 CPU/GPU |
| 管线支持 | 请求前检查 `RenderPipeline.SupportsRenderRequest`；不支持则换适配器/报告无法采集，不把空跑当计时成功 |
| 计时外 | Shader 导入/编译、Feature/材质创建、RT/回读纹理分配、PNG 编码和报告写入 |
| 起点 | 使用当前获授权的相机/配置，不用历史快照覆盖用户正在编辑的视角或参数 |
| 控制变量 | pose/投影/aspect、尺寸/renderScale、输入物体/光照/动画、曝光/后处理、Renderer/Feature 顺序、非被测预算与采样/历史状态 |
| 时间与随机 | 固定/匹配可控 Shader 时间、采样序列与起始历史条件；不可控项记录为限制，不伪称冻结 |
| 路径检查 | 核对真实 Shader/Pass/关键字/uniform；强度0导致整路跳过时，测到的是管线启停差，不是单个算法成本 |
| 默认起步 | 已验证案例用每块8次预热、12次测量、3轮；是起步建议，不是所有效果的固定门槛 |
| 顺序 | A/B 交错或 ABBA、轮间反向，避免先跑完所有A再跑所有B；候选多时轮换顺序 |
| 稳态 | 首次编译/初始化结束后预热；预热不足或后台任务/温控导致漂移时标记失败/未分辨，不事后挑快样本 |
| 恢复 | 使用获授权的临时克隆；finally只恢复本任务拥有且未被并发更新的字段、释放自己的RT/对象，检查原引用/Active/设置/dirty |

不以帧末归还池的 RenderGraph 全局纹理作为跨帧同步/回读目标。使用采集器自己持有的最终请求 RT；实际命中哪条管线仍需上述路径检查。

## 最小原始报告

- 设备/图形API/Unity版本、计时口径、场景及相机投影/pose、分辨率与 Renderer 模式。
- A/B 标签、唯一被测变化、输入/配置或源码签名、实际预算/关键字与历史/采样起点。
- 每轮/块的执行顺序、预热/样本数、逐样本提交段与同步段毫秒；保留所有样本，不静默删异常值。
- 固定和未固定的时间/随机条件、原状态恢复结果、失败/漂移信息、报告路径。

## 相对判读

1. 检查路径、样本非空/有限/正值、同步段不短于提交段、条件可比与状态恢复；不满足就不能给性能结论。
2. 每个尺寸分别计算块中位数；先看同轮 A/B 的相对差，再列总体中位数、P95与块间范围。不要只合并所有样本掩盖漂移。
3. `相对变化 = (B中位数 / A中位数 - 1) × 100%`；负值表示本次B墙钟更低，不自动等于GPU提速。
4. 跨轮方向不一致、块间漂移或差值落在背景波动里：结论为“本次未分辨差异”。需要进一步判断时先排查干扰、再有界重跑，不靠不断加样本追显著性。
5. 有一致且大于观测波动的差异时，只陈述本设备/场景/尺寸/配置的相对趋势；未构造统计检验时不声称统计显著，也不给虚假的统一阈值。

墙钟差包含回读、同步和整条管线的相互影响，不是目标Pass的独立边际成本。画质、GPU纯时间和连续帧率单独验证。

## 项目适配器

按资源 ID `benchmark.ssgi.collector`、`benchmark.ssgi.adapter`、`benchmark.ssgi.checker`、`benchmark.ssgi.contract` 取用现有项目的计时采集、启动、检查和合同；它们仍归实际功能目录。历史数字不能直接拼成新 A/B，功能特有切换和校验不能当成通用效果入口。

新效果保留自己的切换/验证合同，仅复用计时骨架；通用采集库尚未提取。发生实际重复需求时由实现技能评估提炼，不在体系维护中复制业务代码。
