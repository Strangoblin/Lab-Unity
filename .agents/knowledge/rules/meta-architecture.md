# 体系维护约束

架构事实只在 [architecture](../meta/architecture.md) 维护，操作只在 agent-maintenance；本文件只保留边界。

- 体系内容直接维护，不选择 Unity recipe 或调用业务写删移门禁；业务资产仍须任务授权和正常 Unity 门禁。
- 新增前核对已有索引与同主题内容。共享核心只允许 agents、memory、knowledge、skills 四个落点；不恢复软链或旧路径跳转壳。
- 修改路径同步活动读者与解析器；dated 历史、证据和不可变基线保持原字节。平台只明文路由，不能复制共享正文。
- 结构调整须通过架构和隔离 MCP 契约检查，不 reset 生产 state / 审计。路径或资源位置调整不能扩大任务授权或改变安全等级。
- 门禁严格度只由 policy 数据控制；调整 block/warn/off 须人工确认、依据和观察窗口。判定实现保持 judgement 单源，传输层不另立口径。
- 用户授权 / 安全边界不进入可退役集合；人工批准通道须保持平台 hook 封闭和审计。两平台 guard-bash 必须逐字同步。
- 摩擦提案按 [控制事实](../meta/enforcement-policy.md) 评估；E5 的报告、处理与隔离验证取用维护技能，不在此重复命令。
