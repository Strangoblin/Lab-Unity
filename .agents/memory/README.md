先读需要的领域索引，再按问题取用相关记录；不全量加载历史。
当前索引可精炼更新，旧位置与相对链接表示当时语境，按迁移记录回放，不作为当前路由。
dated 记录可以直接改（结论变了就改原文），但改动会出现在 git diff 里 —— 别把别人的结论悄悄改掉。

## 写入规则

| 项 | 规则 |
|---|---|
| 通道 | 平台 `Write` / `Edit` 直接写入。`memory/` 是独立分区：随时可写，**不需要开沙箱**，见[执行契约](../skills/auto-manager/capabilities/execution-contract.md) |
| 历史 | 既有 dated 记录**可以原地改**：结论变了就直接改原文，不必新建副本再在索引里指向前者（2026-10-28 起；历史由 git 兜底） |
| 索引 | 索引（`MEMORY.md` / `memory.md`）随记录同步更新 |
| 位置 | `<领域>/YYYY-MM-DD-<slug>.md`；领域为 `meta` / `unity` |
| 命名 | 日期取记录当天，slug 用主题短语；不用序号或 `latest` |
| 索引 | 同一会话内更新领域索引（[meta](meta/memory.md) / [unity](unity/MEMORY.md)）：索引写取用线索与结论摘要，正文只写一处 |
| 内容 | 区分已验证 / 推断 / 未验证；记录依据、限制与后续条件 |
| 归档 | 记录随仓库提交。只存在于工作区的未跟踪文件不算归档 —— 它没有 git 兜底，删了不可恢复 |

角色只负责判断该不该记、记到哪个领域；流程与证据形式按各角色 AGENT 的"记录"段执行。
