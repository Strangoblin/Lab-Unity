# Hash 变体作用合同审查

可实施的合并：RainDrop `Hash2D` 及 SpecularGI `SpecularGI_Hash22` 共用 `Hash_FracGrid22`；SSL 径向抖动共用 `Hash_Sine21`；VanGogh `Hash/Hash2` 共用 `Hash_Sine21`，保留调用侧的 `-0.5` 映射。RainDrop、SSL 径向、VanGogh Hash2 有意改变具体随机序列；SpecularGI 和 VanGogh 标量 Hash 来源算法保持。

`Hash_Frac22` 仍供 Fin/SSO 使用。保留两个 2→2 算法的理由是实际输入域的空间相关性差异，而非常数不同。所有算法共用范围 `[0,1)` 并不表示可以跨域直接替换。

## 产物与方法

- 可重跑脚本与依赖：见 [归档运行说明](../../../scripts/validation/hash/README.md)；脚本为归档根 `analyze_variants.py`。
- 逐域详细数值、16 桶直方图、所测相关性、原式 source SHA-256：`variant-statistics-report.json`。
- 源合同对照：`../../../scripts/validation/hash/fixtures/final-stage-before.json`。脚本先检查相关原式和实际调用表达式的关键片段，然后按 HLSL 实源转写 NumPy float32 操作；不是执行 HLSL 本身。
- 全部抽样值通过范围及有限性检查；均值、方差、Pearson 相关用 float64 累计。所有方差证据在 JSON 以标准差给出。

本检查不涉及 Unity/Metal 编译、真实 GPU 浮点执行、最终画面、指令成本、完整频谱或感知等价。它只支持随机作用合同和代表输入域上的合并判断。CPU sin、dot 和 GPU 可以不同，不能从 CPU 统计声称 GPU/画面完全相同。

## 实际调用合同

| 消费方 | 输入及时间关系 | 输出及最终作用 | 合并映射 / target |
|---|---|---|---|
| RainDrop | `floor(gridUV)` 的整数格键；另 `(floor(gridUV.x),137)` 的稳定列键。移动 UV 让格键随时间变化，列速度固定；lifetime 使用原 `rand.y*.618+rand.x*.382` | 二通道 `[0,1)`；x 管 coverage、尺度和位置，xy 管位置，xy 联合 lifetime，列 x 管速度和滑落周期 | `Hash_FracGrid22(p)`；保留 seed/周期/范围等后续编排。Shader 无显式 target；只用 float/frac/dot，不升级 target |
| SpecularGI | `uv*_ScreenParams.xy + _FrameIndex*(.754877,.569840)`；FrameIndex 由 temporal 系统提供，无 motion 时返回 0 | 二通道 `[0,1)`；x 经 sqrt 取圆盘半径，y 经 `TWO_PI` 取方位，送入 GGX VNDF 并决定反射射线 | `Hash_FracGrid22(value)` 使用原三乘子原式；保留空间/帧表达式。target 3.5 |
| SSL 径向 | 归一化 UV 加 `frac(_Time.y)`；时间输入每秒回绕 | 标量 `[0,1)` 再 `*2-1`；在固定 dTuv 范围内移动径向 blur 初始采样点 | `Hash_Sine21(p)`，保留标量/时间/范围/幅度/24 taps。target 2.0 |
| VanGogh Hash | 整数环索引；每环固定随机值，时间只在下游调动画相位与速度 | `[-.5,.5)`；环的角度和旋转速度扰动 | `Hash_Sine21(float2(x,0))-.5`；target 2.0 |
| VanGogh Hash2 | 行/列或环/扇整数索引，可有负的行/列键；分格内恒定 | `[-.5,.5)`；调色插值 t 的零中心扰动，下游仍 `_Random` 和 saturate | `Hash_Sine21(float2(x,y))-.5`；有意换序列；target 2.0 |

## RainDrop 合并证据和剩余观感边界

40×36 格代表 Shader 的最多 40 列及小雨滴 6 倍行数（1440 键）；另测实际扭曲可产生的负格键和扩大格键域。

| 40×36 指标 | 旧 RainDrop | 新 Grid |
|---|---|---|
| 通道均值 | (.4987,.4904) | (.4985,.5053) |
| 标准差 | (.2883,.2882) | (.2912,.2857) |
| 通道相关 | .0063 | .0123 |
| 相邻 x 通道相关 | (.0365,.0215) | (-.0372,-.0010) |
| 相邻 y 通道相关 | (-.0417,-.0159) | (-.0064,-.0033) |
| coverage .85 的通过率 | 85.35% | 84.72% |
| coverage .17（默认小雨滴）的通过率 | 17.29% | 17.50% |
| coverage .425（默认水痕）的通过率 | 41.88% | 42.57% |
| lifetime 加权偏移均值 / 标准差 | .4936 / .2100 | .5027 / .2098 |

扩大到 512×256 后，新 Grid 的相邻 / lag50 / lag100 相关绝对值小于 .007，通道相关约 -.00036；没有检出该组 lag 上的明显周期。负格键抽样也维持相近均值、标准差及 coverage。

**少量列键是本次具体观感变化最大的地方。** `(col,137)` 40 列的速度系数均值从 .444 变 .539，标准差 .289→.285，相邻相关 .069→-.403；默认 12 列均值 .423→.502、相邻相关 -.325→-.709。扩到 640 列，新相邻相关为 -.060。不能将这个扩域结果解释为实际少量列画面无差异。4 列、12 列、40 列的原始数值统计均留在 JSON 中；少量固定随机键重新抽样，可能改变实际列速度均值及快慢排列。

12×2 的 24 个默认格键在 coverage .85 下，新旧都通过 19 个；其他 coverage、位置、lifetime 的逐格图案会变。这种有限随机布局变化符合用户允许的“最终随机作用类似”范围，但最终速度观感、排列及形状仍需 GPU/画面对照。

## SpecularGI、SSL 和 VanGogh

SpecularGI 的 Grid 实现就是原三乘子 p3 算法，种子表达式不变。512×256 像素中心在 frame 0/1/127/1023 的均值约 .498～.501、标准差约 .288～.289，所测相邻/lag50/lag100 和通道相关绝对值均小于 .007。128 帧×64×64 像素，跨帧 lag1/2/16/50/100 相关绝对值小于 .003。脚本复用同一原式转写；其 0 差异不是独立 HLSL 实源等价测试。

SSL 在 1920×1080 像素 UV、time fraction 0/.25/.75 的新旧均值约 .499、标准差约 .289。新算法所测相邻 x 相关最高约 .0079，旧约 .0016；相邻 y 及更长 lag 均接近零。60Hz 跨帧 lag1 旧 .0025 / 新 -.0045；lag60 都为 1，保持已有每秒重复种子的时间模式。初始采样偏移的范围和尺度保持。

VanGogh 600×600 行列键，旧 / 新 signed 均值 -.000889 / -.000823、标准差 .28827 / .28838，相邻相关绝对值小于 .005；另测负行列键的结果接近。1000 环标量 `Hash(x)` 与 `Sine21(float2(x,0))-.5` 的 CPU 转写最大差异为 0。Hash2 更改每格具体调色，保留零中心范围、随机幅度和时间编排；不能声称原画面像素保持。

## 拒绝跨域直接替换的反例

| 代表域与指标 | 原 Frac22 | Grid p3 |
|---|---|---|
| 512×256 整数键，lag50-x 双通道相关 | (.764,.863) | (.0026,-.0008) |
| 同整数键，lag100-y 双通道相关 | (.387,.359) | (-.0005,.0014) |
| 1920×1080 归一化 UV，相邻 x 双通道相关 | (.0007,.5968) | (.6039,.6051) |
| 同 UV，相邻 y 双通道相关 | (.0008,-.0027) | (.6363,.6338) |
| 同 UV，通道相关 | .0120 | .2636 |

在整数键上，原 Frac22 的 123.34 / 456.21 乘子形成很强的 50 / 100 格相关；而 Grid 直接用于小步长归一化 UV，会把 SSO 当前主要使用的第一通道抖动变成空间平滑的图案。两者的边际直方图和均值都接近均匀，因而单查输出范围/直方图会漏检。

SSO 的 `Hash21` 同时作用于屏幕 UV 和三平面投影的世界 UV，不能在它的共用 wrapper 中一律乘 `_ScreenParams` 来绕过此问题，否则世界纹理会依赖屏幕分辨率。保持原算法和种子是本次合理边界。Fin 的 UV 为网格插值，seed 为每根独立随机 float；其旋转/尺寸的代表抽样旧新分布都接近均匀，但本次没有独立合并必要，继续保留原 Frac22。
