# Weather 整合需求

日期：2026-10-08。状态：用户已授权实施，模块与预设已完成。范围：Unity Lab 的 Rainy / Sandy / Snowy 屏幕天气后处理。

用户已确认：首版选择单一天气预设，预设内部模块可以分别调节和关闭。新增 Weather 功能并接入 PC Renderer，旧天气与共享噪声资源保留。

范围补充：Weather只负责模块化粒子与氛围；Rainy的blur在整合时抛弃。雨滴折射属于粒子效果，继续保留；镜头水汽遮罩、场景雾与调色属于氛围。移除blur是已明确的视觉变更，不要求Rain最终输出与含blur旧版完全一致。

配套文档：[系统设计](design.md)、[迁移任务](tasks.md)。本文中的资源路径均相对仓库根目录。

## 边界与术语

- Weather 管线：一个正式 RendererFeature 调度天气 Shader，替代三套效果依赖 DebugOutputFeature 的正式运行方式。
- 天气预设：Rain / Sand / Snow 的参数资产；每次只选择一个。
- 两类功能：Particles（屏幕粒子／雨滴折射）与Atmosphere（镜头沉积、场景雾、调色三个可独立控制的子模块）。模块是可独立控制的算法职责，不要求一个模块对应一次全屏绘制。
- 镜头沉积：雨水汽、沙积尘或雪霜边；与场景雾分别控制。
- 迁移基线：当前磁盘代码与实际材质值；Rain的目标基线明确去掉blur，其余逻辑保持原行为。文档、Shader默认值和材质值不一致时，以代码和材质建立迁移预设。
- 首版不包括：多天气同时叠加、天气过渡系统、世界空间降水、真实粒子遮挡、积雪／积水材质联动、自动噪声重烘焙、Volume 区域混合、需要跨相机图传播天气输出的Camera Stack支持。

## 非功能约束

- 开发基线：Unity 6000.3.14f1、URP 17.3.0、当前 macOS Metal；使用 RecordRenderGraph 和 Blitter，不引入旧 Execute / cmd.Blit 路径。
- 保留 TRS.hlsl 的等比空间契约；特征函数在 Weather 家族内共享，先不提升为全项目 Special/HLSL 库。
- 参数资产与管线资源各有一个权威入口；资源和计算状态不能通过隐式全局变量互相覆盖。
- 切换 Shader keyword 或 Profile 后不能残留上一预设的参数、纹理或关键词。
- 缺失 Profile／Shader／噪声或不可采样的相机颜色时应安全跳过并给出可定位诊断；不得静默使用白噪声材质假装已完成兼容。
- 验收记录分别说明编译、运行、GPU数值对照、结构预算与人工视觉观察；不得以数值测试代替视觉或GPU毫秒测量。

## 未纳入首版的可选演进

1. Snow 高度雾／正交支持、统一保留输入 Alpha、修正 Rain 折射长宽比：分别作为行为变更验收。
2. 将旧参数的耦合响应替换为更直观的响应曲线：保留兼容 Profile 及迁移说明。
3. 天气过渡、多天气混合、Volume 区域控制和场景材质天气联动：在首版稳定后另立需求。
