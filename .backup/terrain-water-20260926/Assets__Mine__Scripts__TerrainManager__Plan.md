# TerrainManager — 功能性实验执行计划

> 状态：初版功能性实验已完成；P6 保留后续扩展
> 更新：2026-09-26
> 目标目录：`Assets/Mine/Scripts/TerrainManager/`

## 目标与边界

为 Unity 6 + URP 17+ 的 3D 俯视角游戏生成一张可配置的近乎平面地图。首个实验地图默认大小为 300 × 300 世界单位，以草地为基底，包含村落、麦地、森林三个区域特征及连接地点的道路。初期用不同颜色的简单几何体表示房屋、风车、树、草和小麦，验证从数据生成到地表着色与内容分布的完整链路。

首轮只要求功能正确和可重复生成。暂不实现 `PlantGenerator`/`PlantManager`、真实建筑预制体、天气、动物、复杂水体、山体、全图 WFC、运行时流式加载或最终美术材质。数据契约预留可选高度及扩展字段；基础高度默认为零，仅允许将来加入小幅下凹等变化。

## 术语与默认假设

- **地图大小**：300 × 300 指世界空间的 XZ 尺寸，不等于逻辑单元数量。
- **逻辑网格**：保存区域、道路、可选高度等权威数据。初版建议 1 世界单位/格，即 300 × 300 个单元；格距是配置项。
- **地表网格**：用于绘制的分块 Mesh，从逻辑数据采样；建议先以 50 × 50 世界单位为一个渲染块，避免单块顶点过多。分块尺寸是实现起点，不是固定规则。
- **区域**：`Grassland` 为默认区域；`Village`、`WheatField`、`Forest` 为覆盖它的区域特征。森林与草地可共享底色，但语义必须区分。
- **道路**：由连续路线、宽度、覆盖遮罩和路面类型共同表示。路面类型可随所在区域变化，例如草地段为黄土路、村落段为石路。
- **占地**：内容分布时用于避让道路和其他内容的空间范围；属于分布结果，不回写基础地图数据。

## 可验收需求

| ID | 要求 | 首轮验收 |
|---|---|---|
| REQ-01 | 地图大小、逻辑格距和随机种子可配置 | 更改尺寸后仍可生成；同配置和种子生成相同数据摘要 |
| REQ-02 | 生成草地基底和村落、麦地、森林区域 | 四种区域都能在调试视图或数据统计中识别；区域在地图边界内 |
| REQ-03 | 生成连续的地点连接路线，并按区域决定道路外观 | 路线图连接目标地点；路面在区域交界处不断裂 |
| REQ-04 | 地表网格和着色读取同一份地图数据 | 区域/道路数据变化后，重新生成会同步改变地表形状或颜色 |
| REQ-05 | 分布器输出房屋、风车、树、草和小麦的占位计划 | 占位物出现于相应区域；建筑不与道路或其他建筑重叠 |
| REQ-06 | 重新生成能替换旧实验结果 | 同一场景重复生成时没有旧块、旧占位物或重复材质实例残留 |
| REQ-07 | 无效配置与生成失败可定位 | 尺寸、格距或缺失材质非法时给出明确错误，场景不提交半成品 |

## 组件与职责

| 组件 | 输入 | 输出及职责 |
|---|---|---|
| `TerrainManager` | 配置、种子、场景引用 | 顺序调用三个生成器、提交可视化结果、清理旧结果；不持有区域和放置算法 |
| `TerrainDataGenerator` | 地图配置、种子 | 生成 `TerrainMapData`：区域、地点、道路、可选高度；基础数据的唯一权威来源 |
| `TerrainMeshGenerator` | `TerrainMapData`、地表配置 | 生成分块地表 Mesh 与着色输入；不得改变地图数据 |
| `TerrainStuffDistributor` | `TerrainMapData`、分布配置 | 生成 `TerrainStuffPlan`：类别、位置、朝向、尺寸、占地；不实例化场景物体 |
| 实验表现适配 | 地表结果与 `TerrainStuffPlan` | 将地表提交给 MeshFilter/Renderer，并用简单几何体显示放置点；后期替换为预制体与植物系统 |

依赖方向固定为：`TerrainDataGenerator → TerrainMapData → TerrainMeshGenerator / TerrainStuffDistributor → TerrainManager 提交表现`。Mesh 与分布器彼此不依赖。生成方法可以先同步执行；若以后改为异步或分块任务，上层契约仍以本次生成结果为准。

## 最小数据契约

`TerrainMapData` 包含版本、种子、世界原点、世界尺寸、格距和单元尺寸；每个逻辑单元至少有区域类型与可选高度。道路单独保留连续路线/连接关系，并提供可采样的覆盖率与路面类型。地点至少有类型、中心、范围和稳定 ID。区域与道路是正交数据层：一块麦地可被道路穿过，道路不会把该处的麦地区域改写掉。

`TerrainSurfaceResult` 包含地表分块的网格、世界范围和着色输入。初版建议用从 `TerrainMapData` 烘焙出的地表颜色/控制纹理驱动 Shader；具体通道编码在实现着色器时确定。每个分块使用统一世界坐标采样，保证相邻块颜色与边缘顶点连续。双网格在此表示“逻辑数据网格 + 表现网格”，后者不是第二份地形权威数据。

`TerrainStuffPlan` 是有序的放置记录集合。记录至少包含稳定 ID、内容类别、变换、占地边界和来源区域。占地检查在分布器内部进行，优先保留道路和关键建筑位置，再布置密度较高的树、草和小麦。表现适配器只负责把这些记录显示为几何体，不决定分布。

首轮使用独立的随机子种子生成区域、路线和内容，避免仅修改草的密度就改变村落布局。相同输入在同一实现版本内应产生相同结果。

## 初版生成顺序

1. 验证配置；建立共享坐标系与确定性种子。
2. `TerrainDataGenerator` 填充草地基底，确定村落、麦地和森林的位置与范围。
3. 根据地点建立连接关系，生成连续路线；按区域映射路面类型，生成道路覆盖数据。
4. `TerrainMeshGenerator` 采样数据生成分块平面 Mesh；可选高度只影响顶点 Y 值。同步生成 Shader 使用的区域/道路颜色输入。
5. `TerrainStuffDistributor` 在道路和建筑占地约束下输出放置计划。村落放房屋，麦地放风车与小麦，森林放树，剩余草地区域放草；数量、间距与占地参数由配置控制。
6. `TerrainManager` 在全部结果有效后替换场景中的旧生成结果；实验表现层绘制 Mesh、设置地表材质并显示分类占位几何。

路线生成和占地分配先采用可读、可测试的规则/搜索算法。WFC 保留为未来可替换的复杂布局求解器，首轮不将其作为完成条件。

## 阶段任务与依赖

- [x] P0 规划工作区：记录需求、数据契约、生成顺序和验收标准。
- [x] P1 数据骨架（REQ-01、REQ-02、REQ-07）：建立配置、坐标转换、`TerrainMapData`、种子分流及 `TerrainDataGenerator`；用数据统计验证四类区域。
- [x] P2 道路数据（REQ-03）：生成地点连接图、路线及道路覆盖/路面类型；验证连续性、边界和区域交界处样式。
- [x] P3 地表与着色（REQ-04）：实现 `TerrainMeshGenerator`、分块拼接和 URP 地表 Shader 数据输入；验证颜色图绑定和 Shader 编译。
- [x] P4 内容分布（REQ-05）：实现 `TerrainStuffDistributor` 的候选点、占地检查与稳定输出；以纯数据验证避让规则。
- [x] P5 场景实验（REQ-04、REQ-05、REQ-06、REQ-07）：实现 `TerrainManager` 与简单几何表现；在默认 300 × 300 地图上端到端生成、重复生成并检查清理。

任务依赖为 `P1 → P2 → P3/P4 → P5`；P3 和 P4 在 P2 的数据契约稳定后可独立推进。每个阶段完成时更新本文件复选框，并记录实际采用的配置及验证结果。

## 首轮测试与完成标准

- EditMode：验证种子重复性、坐标索引边界、区域覆盖、道路图连通、路线连续、建筑占地不重叠及道路避让。
- 场景集成：默认配置生成完整 300 × 300 地图；四类区域和路面差异可见；房屋、风车、树、草、小麦均由数据驱动出现。
- 重新生成：变更种子会改变分布；相同种子还原相同布局；重复执行不会保留上一轮的几何或 GPU 资源。
- 性能记录：记录数据、Mesh、分布和提交各阶段耗时与对象数量。首轮不设未经目标设备实测的硬时限。

## 留到后续细化的决策

区域形状算法、区域比例、道路宽度与密度、各类占位物密度、地表 Shader 控制纹理编码、预制体资源与植物渲染方式，均在相应阶段依据实验效果确定。接口应允许更换这些策略，而不影响其他阶段对 `TerrainMapData` 的读取。

## 初版交付与验证记录

运行入口为 `Assets/Scenes/AlgorithmScene.unity`：打开场景并进入 Play Mode，`TerrainManager` 自动生成。可在 Inspector 调整地图尺寸、种子、道路宽度及各类占位物数量；`TerrainManager` 的右键菜单支持重新生成。编辑器菜单 `Tools/Terrain/Prepare AlgorithmScene` 可重设实验入口与俯视相机，`Tools/Terrain/Validate Experiment Data` 可运行数据验证。
